# Demo mode UI visual QA — 2026-10-11

## Setup

- Android emulator: `emulator-5554`, Android 15, 1080 × 2424 screenshot resolution.
- App opened in Demo mode. This is a visual pass on the emulator, not a physical Seeker device.
- No app source was changed during this inspection.

## Confirmed issues

### 1. Invite-code action is covered by the Android keyboard

- **Screen:** Join an Oath → Enter an invite code.
- **Reproduction:** open Join, choose “Enter an invite code,” focus the field.
- **Observed:** the soft keyboard opens while the fixed “Find Oath” button stays anchored at the bottom of the app. The keyboard covers the button, so the user cannot see or tap the next action while entering the code. Dismissing the keyboard shows the disabled button again.
- **Suggested fix:** apply keyboard-aware layout/insets to this screen so the action remains visible above the keyboard, or make the form scroll/reserve enough space while the field is focused.
- **Severity:** Medium; blocks the obvious next step while typing, although the user can dismiss the keyboard.

### 2. Invite-code placeholder has very low contrast

- **Screen:** Join an Oath → Enter an invite code.
- **Observed:** placeholder example `IRON-7K2Q` is dark gray on a dark input surface and is difficult to read compared with the field label and helper text.
- **Suggested fix:** check the placeholder text color/opacity against the design tokens and raise contrast while keeping it visually secondary to entered text.
- **Severity:** Low; readability/accessibility issue.

## Developer-build overlay collision

- A large floating gear button from the dev menu stays at the top-right on Demo screens. On Today, Oaths and Profile it overlaps the app's notification/settings header controls; the bell and gear visibly collide. On screens without those controls it still occupies a large part of the header.
- This appears to be the development menu affordance, not app content. Hide it in normal app builds and reposition it in development builds so it does not cover screen controls.
- The supplied Join screen screenshot shows the dev menu expanded over the right side of the app. It covers the `Join an Oath` header area and clips the `Enter an invite code` heading. Recheck the Join screen's horizontal layout at this viewport and ensure the dev-menu panel cannot obscure app content while it is open.

## Checked; not confirmed as defects

- Today’s Oath carousel appeared clipped during the first transition frame, then settled into a correctly centered card after about three seconds. Treat as an animation artifact unless it reproduces after the transition.
- Bounties horizontal card rows intentionally show a partial next card; no stable clipping defect was confirmed there.
- Profile and Oath detail have fixed bottom actions/navigation over scrollable content. Some lower content is initially behind that area, but scrolling is available; no inaccessible row was confirmed in this pass.
- Oaths list, Bounties, profile header/card, group Oath detail, and the create/join entry sheet otherwise rendered without a persistent visual break during this pass.
